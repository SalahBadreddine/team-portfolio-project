## Retrospective Analysis

Throughout this project, our team learned how essential communication and coordination are when working collaboratively on a shared codebase. From the beginning, we divided the responsibilities clearly — one member focused on the structure and layout of the main page, while others created their personal profile pages and helped refine the design. This distribution of work allowed us to progress in parallel, but it also required us to learn how to manage integration carefully.

The most significant technical challenge we faced was maintaining consistency in the project’s structure while multiple people worked on the same files. Early on, we realized that editing index.html simultaneously often caused conflicts and overwrote each other’s changes. To address this, we established a clear workflow: everyone worked in a separate feature branch, regularly pulled updates from the develop branch, and submitted pull requests for review. This approach minimized conflicts and ensured that each contribution was reviewed before being merged.

One of the main merge conflicts occurred when two members added their cards to the main page using slightly different HTML structures. Git flagged these lines as conflicting, and the code couldn’t merge automatically. We resolved the issue manually by comparing both changes, standardizing the structure of all cards, and re-testing the layout to make sure everything displayed correctly. This experience helped us understand how merge conflicts happen and how to fix them efficiently.

Overall, the pull request and peer review process played a huge role in improving our final product. Reviewing each other’s work also encouraged shared learning, while everyone became more familiar GitHub workflows. By the end, our teamwork evolved from individual contributions to a well-coordinated collaborative effort, resulting in a clean, functional, and visually consistent final website.
